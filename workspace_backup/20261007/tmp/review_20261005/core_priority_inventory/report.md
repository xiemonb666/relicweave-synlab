## Shortest real bridge and blockers

The first blocking edge is literal and narrow: VF can emit a mother package, and PG can validate its forge.asset.v1 contract, but PG run rejects that package type as unsupported before launching the solver. Implement one bounded importer that turns a single VF surface/STEP into a versioned material-point set plus cavity/void-aware horizon mask, preserving units, frame, manifest/source hashes, material fields, and mother-triangle lineage. The existing static STEP probe can inform this gate but is not itself the native initialization gate.

After that edge, the minimum chain still needs two connected outputs: (1) run one fixed-mesh native load/fracture case with a complete per-step directed-bond history and energy/work accounting; (2) reconstruct geometric crack faces/fragments from those histories and map the fragment surfaces back to the original mother mesh/regions/fields. The current endpoint graph components cannot substitute for either output. Until those outputs exist, source labels, event labels, fragment geometry, historical R2, and final label export remain UNKNOWN or unimplemented.

Suggested ownership keeps the work incremental: VF owns a single frozen mother-package fixture and its provenance/semantic fields; PG ingress owns surface-to-volume sampling, cavity mask, and mother lineage; PG mechanics owns one CPU native run with step history and energy/work evidence; PG fracture/export owns paired crack-surface and fragment reconstruction plus mother-to-fragment labels. The first acceptance point is just “one VF package initializes a native PG material-point graph with void crossings excluded and source lineage retained”; this does not require adding every vessel family, solver family, training pipeline, or production host first.
