# Full-source backup inventory (prepare only)

This is a read-only inventory and candidate action manifest. It performs no copy, staging, commit, push, branch change, or persistent Git configuration change. Root separately authorized only three exact repository-local `.gitattributes` append-only rules; their original bytes are preserved as explicit workspace-root candidates. The exact action list still needs root review and a new execution GO.

inventory.json records source paths, bytes/SHA-256, Git HEAD blob identity for tracked candidates, ignored status, exclusions, >50 MiB flags, and credential path/status only. explicit_action_manifest.json lists exact proposed stage/copy destinations. Root-external authored files map to the existing SynLab repository at workspace_backup/20261007/<original-relative-path>. Final handover files also receive byte-identical canonical copies in docs/handover/20261007/ for single-repository restore.

For tracked bytes that differ from HEAD only by CRLF/LF normalization, the plan proposes a raw snapshot under docs/backup/20261007/raw_source/<original-repo-relative-path>. Root authorized a narrow `/docs/backup/20261007/raw_source/** -text` rule in each existing repository’s `.gitattributes`; original attribute bytes are included under `attribute_snapshots/<repo>/.gitattributes`. No other attributes or persistent Git configuration changed. New paths with text/eol/filter attributes are separately flagged.

Large files are reported by path and size. Credential-like paths are reported by path/status only. Three selected bounded replay NPZ inputs and exactly two portable JUnit fixture XML files are explicitly tracked; other generated datasets and non-CLOSED XML stay excluded. The 100 evidence_files referenced by the frozen physics-core status pins are individually mapped to an exact existing HEAD blob, an exact planned same-path candidate, or a raw-byte snapshot candidate. SCIENCE98 accepted plan versions, execution receipt, independent reports and orchestrator are explicit candidates. Mutable or unreviewed code remains pending and no backup promotes scientific or physical qualification.

Final master and handoff DOCX are included only after final writer QA and exact SHA/byte pins are supplied and frozen. Fixed delivery sidecar: `relicweave-synlab/docs/handover/20261007/BACKUP_DELIVERY_RECEIPT.json` and `.md`, generated after the three code commits/pushes and outside its own recorded commit-set.

After the frozen inventory is built, `export_frozen_maps.py` derives `CODE_COVERAGE.md`, `WORKSPACE_SOURCE_MAP.json`, and `SUPPLEMENTARY_EXPORT_MANIFEST.json` without rebuilding or self-hashing the inventory. It also plans an exact copy of the frozen action manifest as `docs/backup/20261007/CONTROL_ACTION_MANIFEST.json`; the much larger full inventory stays local. These supplementary exports require their own root-reviewed exact manifest and are not silently folded into the main inventory.

`execute_closeout_backup.py` is the separately frozen exact-manifest execution tool. It accepts no repository writes unless `--execute` is paired with both the reviewed action-manifest SHA in `--root-go-confirmed` and the separately reviewed three-export SHA in `--root-go-supplementary-confirmed`; it then rechecks source pins, destinations, repository branches/HEADs/remotes, exact staged and committed blob sets, and performs ordinary non-force pushes. It rejects generated/runtime/cache/credential paths and classifications, scans selected text sources for high-confidence credential patterns without printing matched values, and records the bundled Git binary SHA-256. It uses a per-command `core.autocrlf=false` and the fixed aggregate execution receipt path `execution_receipt.json`. Its presence does not itself authorize a run; the exact inventory and supplementary manifest still require root GO.

Small stable plans, receipts, evidence, and configuration files under workspace or repository `tmp/backup_coordinator/` paths are included at their original paths when they use the approved text/config suffixes and are at most 5 MiB. Authored code and source snapshots are included independently of that size/extension rule. The current self-referential inventory/action-map exports, post-push receipt, transient mutation logs, generated outputs, and larger files remain out of the candidate manifest.

This README is finalized before inventory scanning. The inventory records and verifies its exact pre-scan byte size and SHA-256; the builder does not rewrite it after collecting source pins.
