# Addendum: current V2 builder and proposed verifier

This addendum reviews `build_closeout_inventory_v2.py` and `verify_manifest_readonly.py` by reading source only. Neither script was executed by me. A generated inventory and action manifest appeared while the review was in progress, so I checked selected path membership in those JSON files using PowerShell's JSON parser. I did not read source payloads or perform Git/blob readback.

V2 resolves several initial-draft omissions, and the generated inventory confirms that all three selected replay NPZ paths, the five reference DOCX files, the root `_scratch_heads.py`, three `data/**/*.py` scripts, representative source suffix snapshots, and sampled VF/PG review JSON paths are present. The SynLab toy-endpoint JSON fixtures and 1,095,598-byte `bond_states.csv` are in the full inventory; they have zero action rows because they are already on branch. The six named root runtime/install trees are listed as excluded subtrees. The first-pass report records the earlier source findings; this addendum supersedes those findings where V2 now fixes them.

The generated files were created at 12:35:25 local: `inventory.json` is 21,572,712 bytes with 23,638 entries; `explicit_action_manifest.json` is 7,574,492 bytes with 5,909 actions. The builder was modified after that time and its current hash is not recorded in the inventory. At the last check it was 38,257 bytes, SHA-256 `f9addfaf0555ccf1fc70521cf20efdebda9f5bf1504702a3575387350ea6f1aa`. The V1.47 closeout DOCX is an action even though the manifest's pending-documents note says the master is awaiting QA/freeze and a draft should not be pinned. These conflicts mean the generated files need a frozen builder/input binding and explicit root disposition before they are an execution manifest.

Coverage gaps remain. The root-external walk still skips every non-code/non-snapshot file below `tmp/backup_coordinator`; the two science plan JSON files checked are absent. The inventory itself also names a SynLab `BACKUP_DELIVERY_RECEIPT.json/.md` sidecar under `pending_documents`, but both files are absent from the generated inventory/actions. Numeric fixtures over 5 MiB are still excluded automatically, and YAML/config fixtures under `output(s)` still hit the generated-path rule before the fixture path rule. Generic review or receipt JSON outside current closed roots and known fixture/basename rules also needs an exact handoff-derived list. The broader snapshot rule can overinclude files such as `truth_test_relations.py.txt` or `inspection_command.py.txt`; inspect those manifest rows individually.

The proposed `verify_manifest_readonly.py` is not sufficient for the eventual postverify. It hashes source paths and checks destination containment and duplicate destinations, but it does not hash destination files or compare raw Git `HEAD` blobs. When given the V2 action manifest, it reads `candidate_actions`, which excludes `already_on_branch` files. The V2 builder also labels an OID from `git ls-files --stage` as `git_head_blob_oid`; that is an index-stage object, not a direct `HEAD` tree lookup. The eventual postverify must map paths from `git ls-tree -r -z HEAD`, compare raw `git cat-file blob` bytes and hashes against source and destination for every approved path, and verify exact commits/pathsets, remote branch refs, and index cleanliness.

The current tracked-status observation remains: PGFrag and VesselForge produced empty `git status --short --untracked-files=no` output; SynLab reported `M docs/a12/HANDOVER.md`. I did not edit that file, and its origin is unknown. No copy, commit, push, or other repository mutation was performed by this review.
