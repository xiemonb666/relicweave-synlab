**A6.6 候选搜索与“多重思考”机制**

| 创新候选 | 定义 | 为什么适合“给定碎片找邻片” |
| Candidate Hypothesis Evolution | 每个候选在内部 tick 中拥有 belief、不确定性和证据轨迹，可被支持、挑战、降级或恢复。 | 任务本身需要反复检查断口、纹样、整体曲率等不同证据，而非一次 embedding 决定。 |
| Active Evidence Routing | 由当前候选歧义和不确定性决定下一步查看哪一模态／区域／候选。 | 不同碎片最有区分力的证据不同；固定多模态融合浪费计算且容易被低质证据污染。 |
| Reversible Candidate Pruning | 候选分 Active / Dormant / Rejected；暂时低分可休眠，只有强反证才永久拒绝。 | 低质量输入容易把真邻片过早踢出 Top-K；后续新证据应允许 candidate resurrection。 |
| Uncertainty-Adaptive Thinking | 依据候选熵、Top1/Top2 margin、冲突量、轨迹稳定性分配内部 tick。 | 简单碎片少算，磨损／无纹样／hard negative 多的碎片多想。 |
| Hierarchical Deliberation | 先 query self-deliberation 得到稳健检索表示，再对粗召回集合做 relational deliberation，最后只对少量候选做高成本物理验证。 | 避免对全库每个候选都跑多轮 CTM；实现“候选越少，思考越深”。 |
| Coarse-to-Deliberative Retrieval | Stage A 高召回粗检 -> Stage B 多轮关系审议 -> Stage C SE(3)/表面互补等物理验证。 | 与现有 M 候选预算兼容，并把论文机制放在最需要判断的精排阶段。 |
