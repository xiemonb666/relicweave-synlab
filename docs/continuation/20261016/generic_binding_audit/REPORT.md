# Generic mother binding audit

Read-only architecture audit, 2026-10-16. No solver was run and no PG or SynLab code/output was changed. The only new artifact is this report.

## Finding

There is a viable source-identity route for a future native run: use the VF run05 exterior-triangle sidecar, whose per-triangle `original-brep-face-NNN` values were derived through individually exported STEP face witnesses and OCC parent maps, then bind those FIDs to the frozen source `face_lineage.json`. Join all native mesh and event data by the original Gmsh node/cell tags and exact connectivity, never by row position, coordinate proximity, Z bands, or a numeric role code. Hash the entire source chain and make the ancestry scope explicit.

This route provides geometry/data plumbing only. `run05` creates a diagnostic two-volume partition at `x=0`; it has no cohesive/native event or fracture result. Its result explicitly says `fracture_or_fragment_result=NOT_CREATED`, `physical_material_validity=NOT_ASSESSED`, and `solver_qualification=NOT_ESTABLISHED`. The existing A12 packet is a separate, accepted *preinserted weak-seam diagnostic* on a concentric spherical bowl. Neither artifact qualifies observations or targets as training data for native fracture.

## What the inspected contracts establish

`reference_generator.load_reference_mother()` checks source hashes for `surface.npz`, `section.json`, and `face_lineage.json`, binds triangles to serialized source face lineage, checks the linked geometry report and provenance, and verifies a closed, oriented surface and reported dimensions. It exposes `geometry_array_sha256`, `source_file_sha256`, `candidate_status`, `source_profile_fidelity`, and semantic source-face roles on the returned mother. It uses `root.name` as `mother_id`, so that name alone is not a content identity. The actual daily Aberdeen candidate is `SIZE_REFERENCE_GEOMETRY_CANDIDATE_ONLY`; the linked catalog record supports the listed dimensions, while its provenance explicitly says the profile is not reconstructed, foot/base/wall details include design assumptions, and physical properties are unknown. Its structural CAD PASS is not a specimen/profile or material review.

VF run05 upgrades the *mesh ancestry evidence*, not source-object qualification. Its `audit_receipt.json` is `PASS_WITNESS_ANCESTRY_TETRA_MESH`; all 44,182 exterior Tri3 faces have exactly one known source FID and role across 16 source faces. The `mesh.npz` sidecar stores aligned `exterior_triangles`, `exterior_source_face_ids`, `exterior_roles`, `exterior_ancestry_exact`, original node tags, and original cell tags. The MSH 2.2 only names physical groups `source_exterior` and `cut_interface`; exact FIDs are in the receipt-bound NPZ sidecar, not in those coarse group names. The 356 interface triangles have no source exterior FID, as expected. The audit scope says OCC witness ancestry is conditional on declared kernel tolerances, not literal TopoDS identity across STEP or exact metrology.

The independent readback at `experiments/continuation_20261016/root_v6_run05_readback.json` binds the MSH rows back to NPZ node/cell IDs and ordered T4 corners. It reports 86,624 T4s, 25,748 NPZ node rows, 25,579 serialized MSH nodes, and 169 unused NPZ node rows. The readback explicitly uses original tags for identity; coordinate serialization agreement is tolerance-checked (maximum absolute delta about `6.94e-18 m`), not binary equality. A consumer should preserve that distinction and must not silently treat all NPZ rows as MSH nodes.

The existing packet at `pgfrag/data/continuation_20261015/native_cohesive_fragments_v6/` is intentionally narrow. Its manifest binds the run receipt, frozen case, forge manifest, and packet files by SHA-256; qualification is `PREINSERTED_WEAK_SEAM_UNCALIBRATED`, with `physical_pass=false` and `pretrain_eligible=false`. Its forge asset is `forge.asset.v1` for a procedural concentric lower hemisphere. `export_native_fragments.py` identifies spherical shells using hard-coded radii and center and paints using global-rest-Z bands. A12's `native_cohesive.py` verifies file hashes, T4/component closure, cohesive failure evidence, and the boolean `source_exterior_ancestry_verified`; however, its source schema has no external mother identity or per-face BREP FID/role field. It requires the old weak-seam/uncalibrated qualification and a `forge.asset.v1` payload, then samples appearance with `_RestWorldZAppearanceSampler`. The existing `face_region_code` values are renderer regions, not VF FIDs or a reusable semantic face taxonomy. Reusing them for the daily mother could mislabel features such as the foot.

## Minimal binding contract to implement next

Add a generic, read-only source-binding record before changing the native solver or A12 renderer. It should contain:

- A stable binding ID derived from canonical, ordered source hashes; a human-readable `mother_id`; source schema/version; and explicit source/profile/physical qualification values copied from VF provenance without promotion.
- Hashes for the source `solid.step`, canonical `daily_native_named.step`, `section.json`, `face_lineage.json`, `native_face_identity.json`, `witness_manifest.json`, v15 receipt, run05 driver snapshot, `mesh.msh`, `mesh.npz`, `result.json`, and `audit_receipt.json`. Record byte counts where receipts provide them.
- The exact source-face table: `source_face_id`, source native-face index, role, source segment indices, source-face witness hash, and ancestry scope/status. Preserve `original-brep-face-NNN` as the stable FID key; do not identify a face by its ordinal alone without the bound identity manifest.
- Mesh tables keyed by original Gmsh node tag and cell tag, with NPZ row index only as an explicit storage locator; ordered T4 connectivity; and each exterior face's ordered native node tags, FID, role, and verified ancestry flag. Keep interface faces explicitly source-FID-null and mark them as partition/interface geometry.
- A lineage scope string stating that post-insertion bulk row/local-corner identity is conditional on the native backend preserving it. Exact rest-coordinate consistency is a consistency check, not independent proof that persistent cell IDs distinguish coincident cells. Do not claim QP ordinal stability across insertion without separate native-backend quadrature evidence.
- Separate qualification fields for geometry ancestry, source-profile fidelity, physical/material validity, solver/fracture status, observation provenance, and training eligibility. Unknown or absent values fail closed; they must never inherit a positive status from structural CAD, a prior weak-seam packet, or an external catalog record.

The producer's existing `exterior_source_face_ids` sidecar is a useful source table input, not a standalone trust root: verify it against the NPZ hash in `result.json`, the run `audit_receipt.json`, and the frozen witness/source hash chain. In a native run, propagate this FID for every unbroken exterior face; a broken cohesive face should retain its source facet identity and two source-parent cell IDs through a separate event ancestry record. An unrecognized/ambiguous FID, changed cell connectivity, missing lineage, or unresolved qualification should block binding.

## Bounded implementation slice and acceptance

First implement only a generic binding builder/validator and its tests, consuming the frozen VF run05 artifacts. Keep the proposed code ownership to new files `pgfrag/src/pgfrag/mother_binding.py`, `pgfrag/tests/test_mother_binding.py`, and a small immutable receipt under `experiments/continuation_20261016/generic_mother_binding/`. Do not alter `cohesive_vessel.py`, `cohesive_mesh.py`, `cohesive_fragments.py`, or `synlab/integrations/native_cohesive.py` in that slice. This can establish geometry identity without implying fracture capability.

Acceptance should verify: all 16 source FIDs map one-to-one to the frozen role/segment table; all 44,182 exterior triangles map once and only once; interface triangles remain FID-null; node and T4 identities survive MSH/NPZ round-trip through original tags and ordered corners; the 169 unused NPZ nodes remain accounted for; hash or receipt tampering fails; duplicate, missing, ambiguous, unknown, or role-conflicting FIDs fail; row reordering with unchanged original tags preserves identity; coordinates are checked only at the declared serialization tolerance; and candidate/physical/training statuses remain `NOT_ESTABLISHED`/`UNKNOWN`/false. A test must demonstrate that numeric surface tag 5 or any other row/tag ordinal is never interpreted as the VF `foot` role.

Only after that read-only binding slice passes should a separate integration change add this record to a future native run packet and teach A12 to render exterior appearance by verified source role/FID. That later change must preserve all current weak-seam controls and accepted-packet behavior, and must keep training eligibility false until actual native fracture, source/mother qualification, and the relevant physical/data gates independently pass. The run05 planar partition is a geometry diagnostic and is not a substitute for that event.
