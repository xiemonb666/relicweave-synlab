## VesselForge / material-coordinate boundary

- `vesselforge/src/vesselforge/asset.py` manifest dictionary (L67–77) defines an OpenCascade-tessellated exterior/interior surface mesh and B-rep face lineage. `vertices_material_xyz_mm` means immutable rest/material coordinates for later appearance re-evaluation and explicitly “equals initial vertices”; it is not an internal volume-point mapping. `face_region` is surface semantics, with reserved region code 255 not assigned to the intact asset.
- `pgfrag/src/pgfrag/assets.py` validates `vertices_material_xyz_mm` as N×3 and requires it to equal initial surface vertices (L163–176); the package says surface asset mechanical solve is unsupported (L230–232). Therefore the current VF surface contract does not identify interior PG material points or per-point cell support.
- The reviewed evidence/README names one canonical sample: a hollow handled cup with STEP and surface arrays. It is geometry-only QA; none of those fields make it physics-ready or a dynamic fracture truth source.

## RelicWeave / SynLab consumer contract

- `synlab/schemas/runtime.py` dataclasses: `Fragment` has per-face origin/source/interface/side channels and a component ID (L193–210); `InterfacePatch` has event-level interface ID, fragment pair, area, two sample point/normal sets, gap, normal-angle and ambiguity measurements (L215–230); `FractureResult` has fragments, interfaces, event tree, debris and QA (L234–250); relations carry `R2/R1/R0/TINY_CONTACT/UNKNOWN`, area, validity/reason and loss mask (L255–275). These are geometric patch/event types, not directly the PG endpoint tables.
- `synlab/fracture/event.py::run_shared_cut` (L206+) uses one cutter against the same mother for both sides and links complementary clipped interface triangles (`_link_interfaces`, L364+); it is a shared geometry construction. It demonstrates how a synthetic paired patch obtains a common interface lineage. It is not a dynamic PG solver result.
- `synlab/truth/api.py::finalize_clean_truth` (L522+) groups patches by canonical fragment pair/event. `_classify_patch` (L663–730) requires new interface origin on both sides, nonempty unique `source_triangles` (all nonnegative), bounded ambiguity, material-backed sample points and gap/normal budgets. `_merge_pair_edges` (L742–810) applies the area verdict to pair-level measured common surface, not per chunk. `UNKNOWN` remains unknown with `loss_mask=False`; source triangles for an interior PG surface cannot be invented to satisfy this gate.
- Frozen constants in `synlab/fracture/spec.py`: absolute area candidate 0.1 mm² (L39), relative area `1e-4` (following line), gap P95 0.02 mm (L51), ambiguity ratio 0.02 (L53); `fracture_truth.md` also documents material-inside fraction ≥0.90 and normal reversal P95 ≤2°. These are existing SynLab geometric/numerical rules, not proof of physical-grade simulation or a material roughness criterion.
- `synlab/docs/a12/data_contract.md` (Pack, feature/label separation and white-list sections) requires event/revision and lineage in truth/provenance, forbids identifiers, event/interface IDs, relation answers and hidden clean surfaces in deploy features, and preserves `UNKNOWN` outside negative supervision. Relation identity and geometry should be versioned with CleanTruth/PhysicalTruth/VisibleLabels hashes.
- `docs/a12/fracture_realism.md` and `decision_record.md` require event-generated positive-area surfaces, point/mass/isolates retention, independent remesh orientation and fixed material-coordinate field, separate physical calibration and explicit unknowns; tetra faces or post-added roughness do not establish physical fracture.

## Algorithm comparison evidence

1. **PG-compatible nonlocal event surface reconstruction (preferred only as a bounded candidate path).** Preserve the chosen Peridynamics.jl backend. First capture per-step state transitions and initial-vs-dynamic defect provenance; then test an event-conditioned surface inference method over broken-bond neighborhoods in rest coordinates. A common surface can make a valid *synthetic geometric* pair, but the exact set of bonds does not uniquely prescribe this surface. Record method, bandwidth/regularization, source neighborhood, paired-side mapping, numerical residual and uncertainty. Repeated independent remeshing / point-set orientation and `δ/h`, `h`, `dt` tests are required before physical-use claims. Estimate current migration complexity as high; no off-the-shelf PG surface extractor was found in the exact local source examined.
2. **Cohesive/FEM explicit interface (alternative).** First-party MOOSE docs specify a cohesive-zone capability between continuum FE regions and a `BreakMeshByBlockGenerator` that creates split mesh nodes/boundaries for the interface; traction/jump scalars may be emitted. See [official MOOSE Cohesive Zone documentation](https://mooseframework.inl.gov/syntax/Physics/SolidMechanics/CohesiveZone/index.html). This makes paired mesh/interface lineage more direct, but the cited system is quasi-static, interface location/mesh still constrain the path, and the route needs a separately validated dynamic contact/fragments stack. Cost is very high/very high-to-extreme.
