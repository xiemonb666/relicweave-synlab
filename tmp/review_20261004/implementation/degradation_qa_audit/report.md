# A12 physical degradation QA audit

Read-only static audit dated 2026-10-04. No tests, Boolean operations, solver, or Mesh32/64 jobs were run. Findings below describe source-level behavior; they do not claim a geometry run reproduced the triggers.

## Findings

1. **P03 wall-thickness guard can report satisfied without meeting its declared 0.6 mm minimum, and can pass unavailable measurements.** `P03.MIN_WALL_MM=0.6` is passed into `recipe.qa` ([axes.py:557-573](../../../../synlab/degrade/axes.py#L557)). In `_erode_interface`, however, `guard_mm` is only tested for `None`; the loop and `guard_satisfied` compare the *fraction of paired samples losing over half their local thickness* to a 1% budget, never compare `min_damaged_mm` to `guard_mm` ([physical_narrowband.py:247-282](../../../../synlab/degrade/physical_narrowband.py#L247)). Thus a body with measured minimum wall below 0.6 mm can satisfy the guard if the relative-drop fraction is small. The helper also returns `violation_fraction=0` and minimum thickness `0.0` when ROI sampling yields no points or no valid paired rays ([narrowband.py:387-408](../../../../synlab/degrade/narrowband.py#L387)); the caller interprets that as satisfied and emits numeric zeros ([physical_narrowband.py:268-282, 312-319](../../../../synlab/degrade/physical_narrowband.py#L268)). Finally, even when the loop exhausts all iterations with the violation budget still exceeded, `hard` checks only positive loss and watertightness, so `_assemble` can start at PASS ([physical_narrowband.py:274-282, 326-348](../../../../synlab/degrade/physical_narrowband.py#L274)). The narrowband result metadata also omits `min_wall_thickness_mm`; the later `audit_physical` consults only that metadata key and therefore skips its independent minimum-wall threshold for this result ([physical_narrowband.py:77-87](../../../../synlab/degrade/physical_narrowband.py#L77), [api.py:1369-1384](../../../../synlab/physical/api.py#L1369)).

   **Smallest fix area:** distinguish measured/unknown thickness from zero, require adequate paired-sample coverage, enforce the configured absolute minimum, and include guard failure in `realized`/QA status. Carry the declared threshold into result metadata so `audit_physical` checks the same contract. **Useful tests:** zero ROI hits; zero/low valid paired rays; a valid paired result whose minimum is below 0.6 mm while relative violations are under budget; and a result still over budget after the last guard iteration. In each unavailable/failed case expect UNKNOWN/FAIL, never `guard_satisfied=1`.

2. **P03 planned depth is emitted under a measured-recession label.** `planned_max_recession_mm` and `applied_depth_mm` are both set to `depth * scale`, and `measured_max_recession_mm` is set to that same planned scalar ([physical_narrowband.py:296-306](../../../../synlab/degrade/physical_narrowband.py#L296)). The code separately computes `measured_max_vertex_shift_mm` from the accepted result, so the mislabeled value is not needed to represent the available geometry measurement. Because area averaging, pinned rim vertices, normal motion, clipping, and the final intersection can all change the delivered displacement, the current field can overstate or understate observed recession and can make any downstream target check appear measured. **Smallest fix area:** rename it as planned/applied or derive a measured ROI surface displacement from the delivered mesh. **Useful test:** choose a field with pinned/zero-amplitude ROI samples and assert planned max differs from a separately measured delivered displacement; ensure any “measured” key comes from that measurement.

3. **Postassembly FAIL is not propagated consistently into the returned degradation bundle or residual-truth status.** Both narrowband `_assemble` and `apply_damage` downgrade `qa.status` after postassembly failure but leave `qa.realized` at the operator's earlier `True` value ([physical_narrowband.py:63-109](../../../../synlab/degrade/physical_narrowband.py#L63), [api.py:1001-1076](../../../../synlab/physical/api.py#L1001)). `_PhysicalAxis._apply` reads `qa.realized` without checking `qa.status`, stores it as output `meta.realized`, and reports `physical_truth_status` as `label_status` ([axes.py:417-462](../../../../synlab/degrade/axes.py#L417)); `_attach_physical_truth` always calls the updater and sets `UPDATED` without checking physical QA ([api.py:1221-1234](../../../../synlab/physical/api.py#L1221)). `update_residual_truth` does not gate on `physical.qa.status`, and its `qa.pass` covers only relation identity/preservation checks ([truth/api.py:894-898, 974-1000](../../../../synlab/truth/api.py#L894)). A consumer that treats `realized`, `label_status=UPDATED`, or the truth layer's narrower `qa.pass` as overall physical acceptance can therefore see success signals beside a failed geometry audit.

   **Existing protection:** postassembly QA checks finite arrays and signed positive volume, so `abs(mesh.volume)` used for ledger construction does not itself hide a winding flip ([api.py:612-715, 847-895](../../../../synlab/physical/api.py#L612)); `audit_physical` reruns those fail-closed checks ([api.py:1297-1303](../../../../synlab/physical/api.py#L1297)); `_PhysicalAxis.measure` turns a recorded failure code into `realized=False` and `AxisOperator.validate` rejects an unrealized positive level ([axes.py:243-261](../../../../synlab/degrade/axes.py#L243), [registry.py:233-247](../../../../synlab/degrade/registry.py#L233)); and the result commit maps only an explicit audit PASS to `QA_PASS` ([api.py:1658-1693](../../../../synlab/physical/api.py#L1658)). These protections do not remove the contradictory status already placed in the returned bundle/truth. **Smallest fix area:** define one fail-closed acceptance predicate (`qa.status == PASS` plus realized effect) for outward `meta.realized` and truth attachment/status; preserve residual diagnostics only with an explicit not-accepted label. **Useful test:** force postassembly failure after an operator reports realized and assert returned meta is not realized, truth is not marked accepted/UPDATED, axis measurement fails, and commit remains QA_FAIL.

4. **Nonfinite inputs are checked late; the observed P03 NaN-depth path fails but leaks NaN into metrics.** `_erode_interface` rejects `depth <= 0` but does not reject nonfinite depth ([physical_narrowband.py:228-243](../../../../synlab/degrade/physical_narrowband.py#L228)). With NaN, comparisons `<=0` and `>0` are false; `_offset_body` therefore moves no vertices ([narrowband.py:270-290](../../../../synlab/degrade/narrowband.py#L270)), while `measured_max_recession_mm` becomes NaN. The operation should eventually be unrealized from zero lost volume; this is not a demonstrated false PASS, but it allows malformed measurements and unnecessary geometry work. Source mesh finite/index checks do exist in postassembly QA and cause a failure, but only after the operator has consumed the mesh ([api.py:612-639, 867-895](../../../../synlab/physical/api.py#L612)). **Smallest fix area:** reject nonfinite parameters and validate source arrays before narrowband geometry; keep downstream finite checks as defense in depth. **Useful tests:** NaN/±Inf P03 depth should fail at recipe entry with a finite-parameter error and no result; nonfinite source vertices should fail before operator work.

## Risk boundary

The `abs(volume)` ledger calculations in narrowband/API are not by themselves a confirmed winding false-pass: `_postassembly_physical_qa` separately records signed volume and fails non-positive source/component volumes. `audit_physical` and `commit_physical_result` also fail closed when their audit result is supplied. The confirmed gaps concern P03 thickness contract/unknown measurements, the planned-as-measured metric, and contradictory realization/label signals before or outside those gates.

Missing input is already rejected: `apply_damage` requires a mesh, and `audit_physical` returns `NA`/`INPUT_UNAVAILABLE` when clean geometry cannot be resolved ([api.py:906-913](../../../../synlab/physical/api.py#L906), [api.py:1279-1285](../../../../synlab/physical/api.py#L1279)). Thus missing geometry is not a confirmed false PASS.
