## R2, wear, UNKNOWN, and GT boundaries

A12's synthetic `truth.api` derives R2 from a shared new fracture surface (`synlab/truth/api.py:667-779`); this is valid synthetic event lineage for experiments, not archaeology and not the current PG branch. Archaeology is a separate source class; no rule requires every R2 record to be archaeological. A PG endpoint broken-bond pair is not a source for either R2 class. Keep missing or ambiguous relations UNKNOWN; the current chain auditor test `test_unknown_relation_value_is_not_coerced_to_r0` covers this source-only invariant, and current aggregate counts retain 212 UNKNOWN rows.

Wear/degradation should preserve the original neighbor label and retain its source reference while recording changed appearance/geometry measurements separately. Current `apply_wear(mesh, ...)` receives only a mesh and is not wired into the production pipeline, so the repository does not yet provide an end-to-end proof of that preservation contract for the exported package. Physical fracture/deformation operators separately declare label invalidations and require evidence-backed recomputation in `synlab/degrade/api.py:403-455`; this should not be reused to reassign an unchanged historical neighbor label after surface wear.

GT belongs in audit/training labels and must not enter inference features. The code has useful feature checks, but the same-SHA legacy deploy package exposes answer-bearing aliases in its metadata. Therefore the practical boundary is still not safe for inference, even though the current numeric model-vector leak is unproven.
